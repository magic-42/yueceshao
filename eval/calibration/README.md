# 重排质量门 τ 标定资产

对应 `docs/rag-rerank-标定.md` 记载的标定协议，把「改阈值前先复跑标定」从一人本机脚本变成仓内可复跑资产。

## 文件

| 文件 | 说明 |
|---|---|
| `calibrate_rerank.py` | 可复跑标定脚本：稠密 top-40 → Cross-Encoder 逐对打分 → sigmoid → 取最高分 → A/B/C 分组统计漏放/误拦 → 输出建议 τ 区间 |
| `queries-A组.txt` | A 组（域内、语料确实覆盖）20 条，是「误拦」的计数来源 |
| `queries-B组.txt` | B 组（近域）10 条，标定文档 §5 已全文列出 |
| `queries-C组.txt` | C 组（完全域外）10 条，是「漏放」的计数来源之一 |

A/B/C 三组共 40 条，全部入仓。**在具备原始 18262 块索引的前提下**，`python -m eval.calibration.calibrate_rerank --config config.json` 可复现 `docs/rag-rerank-标定.md` §3 的分布与 τ 扫表。

索引本身不入库（`.chroma/` 在 `.gitignore` 里，约 200 MB），所以「查询快照入仓」只保证**查询集可复现**，不保证分数可复现：换一份索引（不同语料版本、不同分块参数）跑出来的分布会漂移，此时只能重新标定、重新确认平台区，不能拿文档 §3 的数字当预期值。要逐位对齐文档 §3，需要与标定基线一致的索引——即 `#27` 分块器修正**之前**、含 718 篇、共 18262 块的那份（见文末口径提醒）。

## 用法

```bash
# 1. 权重放本地（不入库），models/ 下需就位：
#    models/Qwen3-Embedding-0.6B   （稠密检索）
#    models/bge-reranker-v2-m3     （Cross-Encoder）
# 2. 装依赖
pip install -r requirements.txt sentence-transformers
# 3. 在仓库根目录跑（40 条查询、CPU 约 15 分钟）
python -m eval.calibration.calibrate_rerank --config config.json
```

> `config.json` 里 `index.persist_dir` 若是相对路径，**相对路径按当前工作目录解析**（不是按 `config.json` 所在位置）——请确保在索引对应的仓库根目录运行，不要从别处调用。
>
> 指错目录时 Chroma 会自动建一个空集合，脚本不会报错，只是每条查询都记 0.000 分。看到三组分数全是 0.000，先查索引而不是查分组标注。

## 输出

- 三组最高分分布（min/中位/max）
- τ 扫表（误拦率 A / 漏放率 B+C）
- 建议 τ 区间（零误拦平台区，及「中部偏下」的建议值）

## 解读漏放率前必读：B 组标注偏宽

B 组按设计是「近域但语料未覆盖」，但实测 10 条里有 **8 条最高分 ≥ 0.55**，命中的多是**确实相关的政策**——`docs/rag-rerank-标定.md` §5 已逐条核对：

| 结果 | 条数 | 说明 |
|---|---|---|
| 分数 ≥ τ（被放行） | 8 | 其中 7 条语料确实覆盖（农机购置补贴→潮农函〔2024〕133号、高标准农田→新府办〔2022〕3号 等），1 条「部分相关」（宅基地使用权纠纷，见标定文档 §6） |
| 分数 < τ（被拦住） | 2 | 语料确实无覆盖：城乡居民养老保险缴费档次（0.504）、村卫生站医生补贴政策（0.520） |

因此 τ 扫表里 **B+C 的「漏放率 40%」不等于「质量门失效 40%」**：C 组 10 条全部被拦住，B 组那 2 条真正无覆盖的也被拦住；被放行的 8 条里，7 条是正确放行，1 条属于「主题相邻但不是答案」的能力边界（标定文档 §6 已单列），不是阈值能解决的事。按「语料里有没有相关内容」的真实口径，漏放接近 0。

要严格统计漏放率，需要按「命中的条款能否回答问题」重标注，那属于开发手册 §3.4 的人工标注集，不在本目录解决。**在重标注之前，不要拿这个 40% 去调 τ。**

## 口径提醒（与标定文档 §6.1 一致）

脚本默认 `--top-k 40`，统计的是 **max@40**。线上默认 `max_attempts=2`（不过门会放大到 80 条重试），`max(sigmoid)` 随候选池单调不减，所以 **max@80 的漏放率会高于 max@40**。要按线上口径复核，需另跑 `--top-k 80` 并对照两列。

另：标定是在 **18262 块**的索引上做的（`#27` 分块器修正之前的切块结果，含 718 篇）。`#27` 合并后新切块为 20099 块，从零重建索引再跑，分数会有小幅漂移，τ 平台区需重新确认。
