# 粤策哨（yueceshao）

基于负面清单规则引擎与 RAG 的粤东西北县域强村公司与合作社**申报前体检系统**：输入帮扶项目描述（简介 / 资金用途 / 建设内容），输出四段式体检报告。

> **免责声明（产品级，随报告强制展示）**：本系统仅为申报前自查辅助参考，**不构成合规判定**，请以政策法规原文及主管部门意见为准。系统永不输出"该项目合规 / 可以申报"类结论。

## 功能

| 段 | 输出内容 |
|---|---|
| ① 适用政策清单 | 匹配的现行政策文件与条款，含条款时效状态与置信标签（明确适用 / 建议确认 / 未覆盖） |
| ② 负面清单命中提示 | 命中的禁止性条款，每条强制标注依据文号＋条款号＋生效日期，命中类型区分"规则命中 / 疑似命中（建议对照原文）" |
| ③ 材料缺项清单 | 按①命中的现行申报指南列出应备材料 |
| ④ 修改建议 | 申报表述层面的改进建议（建议口吻，非判定） |

置信标签由确定性信号驱动（规则命中 / 重排分数 / 时效状态），**不让 LLM 自评置信度**；渲染规则详见团队手册 4.8 节。

## 架构

三个结构性判断（读懂这三条再写代码）：

1. **负面清单不走检索，走全量扫描**——项目描述 × 全部负面条目逐条比对：规则引擎确定性匹配 ∪ 一次 LLM 蕴含复核，命中取并集。第②段不依赖检索召回；
2. **LLM 永远不手打文号**——生成中引用一律用标记 `[Cn]` 指向检索块，文号 / 条款号 / 生效日期由块元数据模板注入渲染，确定性校验器兜底；
3. **版本链是元数据，不是图**——效力状态 / 替代关系 / 申报窗口是文档级字段＋注册表，不建 Graph-RAG。

```
[解析] 查询结构化抽取＋术语归一化
   ├─（并行1）混合检索 BM25＋稠密、时效元数据硬过滤 → Cross-Encoder 重排 → 质量门
   └─（并行2）规则引擎：负面清单全量确定性匹配（无 LLM）
[负面复核] 项目描述 × 全量负面条目，一次 LLM 蕴含判断，与规则命中取并集
[生成] ①③④段单次结构化生成（JSON），标记式引用，chunk 原文逐字入上下文
[校验] 标记存在性 / 上下文包含性 / 姿态禁语 / 免责声明 → 失败重试 ≤2 → 降级显式标注
[渲染] 四段式报告＋免责声明（②段由规则命中模板渲染）
```

技术栈：Python · LangChain · LangGraph · FastAPI · Chroma · SQLite（文号注册表）· 本地 embedding（Qwen3-Embedding-0.6B）与 reranker（bge-reranker-v2-m3）· 静态前端（GitHub Pages）。

## 开发红线（任何人、任何 AI 助手不得违反）

1. **禁止编造文号**：所有政策引用必须来自知识库已核验条目（文号 / 条款号 / 日期以 registry 元数据为准，不凭记忆写）；
2. **LLM 输出不手打文号**：引用走标记式注入，校验器兜底；
3. **姿态禁语**：代码与提示词不得生成"合规 / 可以申报"类结论；免责声明由渲染层强制注入；
4. **审计公告数据不进检索索引**（它是评测出题集，进索引＝评测答案泄露）；
5. **demo 预置案例不得虚构文号与条款**——用知识库真实条目；
6. 政策语料原文不入本仓库（版权与体积），代码通过 registry 字段结构对接。

## 编码规范

- Python ≥3.10：PEP 8，公共函数类型注解＋docstring（模块头注明职责）；
- 配置走环境变量 / `.env` / `config.json`，**不硬编码任何 key**；`.env` 已在 `.gitignore`；
- 日志用 `logging`，不用 `print`；
- 关键路径（分块对齐、时效过滤、引用校验器、规则命中）必须有 pytest 用例；
- 消融开关全部集中在 `eval/` 的配置布尔位，不得散落硬编码；
- 静态检查用 `ruff`（配置见 `.ruff.toml`，本地跑 `ruff check .`）：CI 现为建议模式，存量清零后转强制；
- 中文注释允许且鼓励（团队约定），但标识符用英文。
